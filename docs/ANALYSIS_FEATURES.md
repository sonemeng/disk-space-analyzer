# 深度分析功能说明

本文说明 Tauri 5.0 的重复文件检测、空间快照和文件年龄统计，包括算法、性能成本和安全边界。

## 重复文件检测

检测分为两个阶段：

1. 遍历所选磁盘或文件夹，只记录不小于用户阈值的普通文件，并按字节大小分组。
2. 丢弃只有一个文件的大小组，对剩余候选以 64 KB 数据块流式计算 SHA-256。

只有大小和 SHA-256 都相同的文件才会进入同一重复组。界面显示“可避免占用”，其计算方式是每组保留一个副本后的理论节省空间。

### 安全边界

- 检测过程只读取文件内容，不修改文件。
- 结果仅提供资源管理器定位，不提供自动批量删除。
- 路径和哈希不会上传或发送到网络。
- 任务支持取消；正在读取的大文件会在下一个 64 KB 数据块前响应取消。

### 性能建议

- 整盘首次检测建议使用 100 MB 阈值。
- 对特定项目或资料目录可使用 10 MB。
- 1 MB 阈值会产生更多候选哈希，适合范围较小的目录。

## 空间历史快照

每次完整磁盘扫描成功后，应用自动保存：

- 总容量、已用和可用空间；
- 已扫描文件数；
- 目录 TOP 20；
- 文件类型分布；
- 文件年龄分布。

快照位置：

```text
%LOCALAPPDATA%\DiskAnalyzer\snapshots.json
```

每个盘符最多保留 30 条，超过后删除该盘最早的记录。快照是结构化 JSON，只在本机使用。

## 文件年龄热力图

完整扫描读取文件元数据时，根据 `modified` 时间将文件划分为：

| 分组 | 范围 |
|---|---|
| 最近 30 天 | `< 30 天` |
| 30–90 天 | `30–89 天` |
| 90–365 天 | `90–364 天` |
| 超过 1 年 | `>= 365 天` |
| 时间未知 | 无法读取修改时间 |

年龄统计与容量扫描共用同一次元数据读取，不执行额外遍历。长期未修改大文件列表来自扫描得到的大文件 TOP 25。

### 判断原则

长期未修改不等于可以删除。归档、备份、媒体素材和项目依赖可能长期保持不变。应用只提供候选和定位，最终处理前应确认用途及备份状态。

## 开发者可重建目录（邻居验证）

清理中心与文件夹分析共用 `dev_rules` 规则。分两档：

### 可进清理中心勾选（高置信）

| 目录名 | 父目录标记（任一） | 说明 |
|---|---|---|
| `node_modules` | `package.json`、锁文件等 | Node 依赖 |
| `target` | `Cargo.toml`、`pom.xml`、`build.gradle*` | Rust/Java 构建产物 |
| `__pycache__` / `.pytest_cache` 等 | `pyproject.toml` 或旁侧 `.py` | Python 缓存 |
| `.next` / `.nuxt` / `.turbo` 等 | `package.json` 或对应 config | 前端框架缓存 |
| `obj` / `bin` | `*.csproj` | .NET 构建产物 |

### 仅文件夹分析提示（不进一键清理）

| 目录名 | 原因 |
|---|---|
| `build` / `dist` / `out` | 也可能被用作源码或发布目录 |
| `vendor` | 可能含自维护代码 |
| 通用 `cache` | 仅工具路径提示 |

### 额外保护

- 无邻居标记 → 只标「需确认」，不进清理列表  
- `src` / `lib` / `components` 等源码目录名永不标可重建  
- 开发项默认不勾选；删除前再验证 + 2 小时热保护 + 回收站  
- 清理分析仅在**完整扫描当前盘之后**触发
