# 注册表健康检查

本文说明 Tauri 6.1 注册表检查的范围、安全边界、备份和恢复方式。

## 检查范围

应用只读检查当前用户 `HKCU` 下的三类项目，不请求管理员权限：

1. `Run` 与 `RunOnce`：仅当命令中能够解析出绝对路径，且目标文件确实不存在时，标记为失效启动项。
2. `App Paths`：仅当默认值是绝对路径，且登记的应用程序确实不存在时，标记为失效应用路径。
3. `Uninstall`：仅当安装目录和卸载程序均不存在时，标记为卸载信息残留。

前两类属于低风险可修复范围。卸载信息可能仍被修复工具或企业部署使用，因此只显示建议，不提供自动删除。

## 修复防护

- 前端只提交项目 ID，不能提交任意注册表路径。
- 后端在修复前重新扫描，并只处理仍然存在且属于低风险白名单的问题。
- 单次最多修复 200 项。
- 修改前调用 Windows `reg export` 完整导出涉及的注册表分支。
- 任一备份失败时整个修复立即终止，不修改任何项目。
- 不扫描或修改服务、驱动、COM、文件关联、共享 DLL、系统级 `HKLM` 项目。

## 备份与恢复

备份位于：

```text
%LOCALAPPDATA%\DiskAnalyzer\registry-backups\YYYYMMDD-HHMMSS\
```

每个涉及的分支会生成独立 `.reg` 文件。需要恢复时，先关闭相关应用，再双击对应 `.reg` 文件并确认 Windows 导入提示。导入注册表会覆盖同名值，恢复前应确认备份时间和内容。

## 说明

减少少量失效注册表项通常不会带来可感知的性能提升。该功能的目标是修复明确失效的用户入口，而不是追求夸大的“问题数量”。
