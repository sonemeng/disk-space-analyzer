# 注册表健康检查

本文说明 Tauri 6.1 注册表检查的范围、安全边界、备份和恢复方式。

## 与清理中心的区别

| | 清理中心 | 注册表检查 |
|---|---|---|
| 范围 | 按侧栏所选磁盘分区 | **与分区无关**，仅当前用户 HKCU |
| 触发 | 完整扫描该盘后 | 用户手动点「开始检查」 |
| 操作 | 文件移入回收站 | 备份后删除失效注册表项 |

## 与 Wise Registry Cleaner 类工具的对比（借鉴边界）

Wise 等工具常见能力：多分类深度扫描、定时清理、排除列表、删除前备份 / 系统还原点、可选优化项。

**我们已具备 / 可借鉴：**

| 思路 | 现状 | 后续可做（保守） |
|---|---|---|
| 分类扫描 | 启动项 / App Paths / 卸载残留 | 可增加「可选分类勾选」 |
| 删除前备份 | 已有 `reg export` 分支备份 | 可增加「一键打开备份目录」已有 |
| 排除列表 | 无 | 可加关键字/键路径排除 |
| 铁证再删 | 目标 exe 必须不存在 | 保持，不扩到 COM/服务 |
| 深度清理 | **不做** HKLM/COM/共享 DLL | 不建议照抄全量清理 |

**明确不跟进：** 注册表碎片整理、开机一键狂清、多用户 HKLM 激进清理——误伤面大，与本应用「可还原、可审计」定位不符。

## 检查范围

界面用**下拉**选择扫描模式、用户范围与检查分类。

### 初级 / 进阶 / 专家

| | 初级（默认） | 进阶 | 专家 |
|---|---|---|---|
| 目标 | 安全可修 | 更广扫描 | 含服务/驱动只读 + 关联/SharedDLL 极严可删 |
| 范围 | 主要 `HKCU` | + HKLM/COM/SharedDLL | 进阶全部 + 服务/驱动/文件关联 |
| 服务/驱动 | 不扫 | 不扫 | **只读，禁止删除** |
| SharedDLL | 不扫 | 只读 | 文件缺失时可删**注册表值**（需确认词+管理员+备份） |
| 文件关联 | 不扫 | 不扫 | 目标不存在可勾选删除（二次确认） |
| 自动修复 | 用户级低风险 | + 部分 HKLM/COM（管理员，默认不勾选） | 同左 + 关联/SharedDLL（极严） |

- **当前用户**：扫描 `HKCU` 下所选分类（默认）。
- **所有用户**：始终含当前用户；若**以管理员运行**，附加 `HKEY_USERS` 其他用户启动项（仅建议）。

| 界面分类名 | id | 扫描内容 | 默认可修 |
|---|---|---|---|
| 无效的启动程序 | startup | Run / RunOnce / Policies\\Run | 是 |
| 无效的应用程序路径 | app-path | App Paths 默认值与 Path | 是 |
| 无效的卸载程序 | uninstall | Uninstall 安装目录/卸载命令 | **否**（仅建议） |
| 无效的历史记录 | history | TypedPaths / RunMRU | 是 |
| 无效的文件类型 | user-command | Classes\\Applications 打开命令 | 是 |
| 无效的帮助文件 | help | HTML Help 等用户级帮助路径 | 是 |
| 无效的字体 | fonts | 用户字体注册表指向缺失文件 | **否**（仅建议） |
| 无效的声音事件 | sound | AppEvents 声音 .wav 等绝对路径 | 是 |

**判定原则仍是路径铁证**：能解析出绝对路径且文件不存在才报。  
**仍不自动清理**：COM/ActiveX、SharedDLLs、HKLM 系统服务级项（需更强证明与管理员策略，后续可只读展示）。

## 排除列表

- 用户可添加关键字；命中 **名称 / 键路径 / 命令数据** 任一子串则跳过该项。
- 排除列表保存在本机 `localStorage`（`disk-analyzer-registry-prefs`）。
- 结果行可点「排除」将名称加入列表，下次检查自动跳过。

## 修复防护

- 前端只提交项目 ID，不能提交任意注册表路径。
- 后端在修复前重新扫描，并只处理仍然存在且属于低风险白名单的问题。
- 单次最多修复 200 项。
- 修改前调用 Windows `reg export` 完整导出涉及的注册表分支。
- 任一备份失败时整个修复立即终止，不修改任何项目。
- 不扫描或修改服务、驱动、COM、文件关联、共享 DLL、系统级 `HKLM` 项目。

## 备份与恢复

### 备份到哪里？

| 方式 | 路径 |
|---|---|
| 默认位置备份 | `%LOCALAPPDATA%\DiskAnalyzer\registry-backups\时间戳\` |
| 备份到指定文件夹 | 用户选择的目录下 `DiskAnalyzer-registry-时间戳\` |

两种都会写入 `backup.json`（含 `app: DiskAnalyzer`）和多个 `.reg` 分支文件。

### 恢复是什么意思？

**恢复 = 把 `.reg` 重新导入注册表原键**（`reg import`），覆盖当前对应键值。  
**不是**把文件复制回 D 盘某个文件夹。  
自选目录备份只要含本应用的 `backup.json`，也可一键恢复。

### 检测 vs 删除

| 结果类型 | 能否删除 |
|---|---|
| 可安全修复（绿色） | 可以：勾选后「备份并修复」会先备份再删除失效项 |
| 建议人工复核（黄色，如部分卸载/字体） | 默认不删，只展示 |

### 为何扫描数量往往很少？

本机实测也可能只有个位数：说明当前用户下「绝对路径已不存在」的项本来就少。  
Wise 数量大，是因为扫了 HKLM/COM/SharedDLL 等更宽范围并用更松规则。我们故意严，不是扫坏了。

## 说明

减少少量失效注册表项通常不会带来可感知的性能提升。该功能的目标是修复明确失效的用户入口，而不是追求夸大的“问题数量”。
